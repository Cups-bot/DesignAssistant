# Что я хочу от программы — вводная для нового разговора

Это бриф для того, кто подключается к работе впервые. Здесь не «как сделано»
(для этого есть [ARCHITECTURE.md](ARCHITECTURE.md)), а **чего я добиваюсь и что
уже готово**.

---

## 1. Кто я и в чём суть

Я дизайнер, веду отдел. Программу написал сам, чтобы не создавать вручную папки
проектов: она берёт заказ (из Bitrix по ссылке или введённый руками), создаёт
папку с правильным именем, кладёт туда нужный `.ai`-шаблон, пишет `args.txt`
и открывает Illustrator со скриптом подготовки.

Прав администратора в сети у меня **нет**. Сисадмин — отдельный человек,
за каждой мелочью к нему не пойдёшь.

---

## 2. Чего я хочу — три вещи

### Обновляемая программа, как любая нормальная

Я правлю интерфейс, добавляю кнопку, меняю логику — и **дизайнеры получают это
сами**. Никаких «скачайте новую версию по ссылке», никаких рассылок в чат.
Программа сама ходит в сеть, видит новое и предлагает обновиться.

Это раздражало больше всего: любое изменение означало обзвон пятерых человек.

### Развёртывание на любой машине

Одна и та же сборка должна работать:

- **в офисе** — где рабочие папки лежат на сетевом диске `Y:`
- **дома у дизайнера** — где своя структура на `D:` или `E:`, и сетевого диска
  не видно вообще

Дизайнер не должен ничего настраивать вручную, вычислять пути или ставить .NET.
В идеале — запустил установщик, указал свою папку, работает.

### Новые продукты без программиста

У нас появляются новые виды продукции: крышки, бумажные пакеты, лотки.
Я хочу добавлять их **сам, правкой файла**, а не просить пересобрать программу.
То же с шаблонами: нарисовал новый — он должен доехать до всех.

## 3. Условия, в которых это живёт

| | |
|---|---|
| Офис | сетевой диск `Y:`, там шаблоны и готовые проекты |
| Удалёнка | дизайнер заходит по RDP, видит `Y:` **только внутри сессии** |
| | на своей машине `Y:` недоступен — работают локально |
| Интернет | есть у всех; Bitrix API доступен снаружи |
| Права админа | нет ни у кого из нас |
| Шаблоны | ~360 МБ, 355 файлов, не секретны (уходят клиентам) |
| Дизайнеров | несколько, у каждого свой Illustrator (2022, 2024, 2025…) |

## 4. Что уже сделано

Программа переписана. Коротко — три слоя с разными сроками жизни:

- **профиль машины** (`%APPDATA%\CupsForge\profile.json`) — папки, Illustrator,
  ключ Bitrix. У каждого свой, в репозиторий не попадает
- **каталог** (`catalog.json` рядом с шаблонами) — какие бывают продукты, где их
  шаблоны, куда складывать. Новый продукт = правка этого файла
- **код** — только «скопировать, записать, запустить»

Физических путей в коде нет: всё через логические корни `{templates}`,
`{out.mycups}`, `{base}`.

**Работает:**

- мастер настройки при первом запуске на новой машине
- Illustrator находится сам, любой версии
- обновление программы без прав администратора (в профиль пользователя)
- установщик `install.cmd` — один двойной клик
- раздача через публичный GitHub-репозиторий `Cups-bot/CupsForge-public`:
  опись в git, файлы вложениями к выпуску, скачивается только изменившееся
- самопроверка: `dotnet run --project Tests/SelfCheck` — 163 проверки

**Размер:** ~6200 строк кода, 63 файла в репозитории.

## 5. Что осталось

### Не проверено вживую

Выкладка в раздачу (`push-templates.cmd`) **ни разу не запускалась
по-настоящему**. Логика покрыта проверками, но живого прогона с настоящим
токеном и настоящими 360 МБ не было. Это первое, что надо сделать.

### Новые продукты не заведены

В папке шаблонов лежат готовые `11_Bag` (19 шаблонов пакетов), пустые
`12_Lotki` и `13_Cover`. В каталог они не добавлены — я не решил, куда
складывать готовые проекты и какой способ печати им писать.

### Мелочи

- в раздачу уедет 355 файлов, а каталогу нужно 97 — стоит настроить `.distignore`
- у офисных машин обновление идёт с сетевого диска, у удалённых — из интернета;
  два канала, можно свести к одному
- ключ доступа к Bitrix надо сменить: он лежал в истории git открытым

## 6. Как со мной работать

Мне важно понимать, **почему** так, а не только что получилось. Если решение
выглядит странно — объясните причину, я запомню.

Не спрашивайте разрешения на каждый шаг. Если задача понятна — делайте
и покажите результат. Если развилка настоящая (например, данные уходят
за периметр компании) — тогда спросите.

Проверяйте на деле, а не «должно работать». У меня уже было несколько случаев,
когда «готово» оказывалось неработающим: скрипт не запускался из-за кодировки,
каталог молча подменялся встроенной копией, кнопка залипала после случайного
нажатия Enter.

После правок прогоняйте самопроверку:

```bash
dotnet run --project Tests/SelfCheck
```
