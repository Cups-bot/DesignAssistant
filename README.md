# CupsForge

Создание проектов дизайна: папка, копия .ai-шаблона, `args.txt`, запуск Illustrator
со скриптом. Заказ подтягивается из Bitrix по ссылке либо вводится руками.

## Устройство

Три слоя, у каждого свой срок жизни. Смешивать их — то, из-за чего программу
раньше приходилось размножать под каждого дизайнера.

| Слой | Что описывает | Где лежит | Как часто меняется |
|---|---|---|---|
| **Профиль машины** | папки, версия Illustrator, доступ к Bitrix | `%APPDATA%\CupsForge\profile.json` | у каждого свой |
| **Каталог** | какие бывают продукты, где шаблоны, куда складывать | `catalog.json` в папке шаблонов | раз в квартал |
| **Код** | скопировать, записать, запустить | эта программа | редко |

Физических путей в коде нет. Каталог адресуется **логическими корнями**
(`{templates}`, `{out.mycups}`, `{base}`), профиль превращает их в настоящие папки.
Поэтому одна и та же сборка работает и в офисе с диском `Y:`, и дома со своей
структурой.

## Добавить новый продукт

Пересобирать программу **не нужно**. Всё в `catalog.json`:

```jsonc
{
  "id": "mycups-lids",
  "title": "MyCups — крышки картонно-алюминиевые",
  "typeTitle": "Крышки",              // как назвать в списке ручного ввода
  "brand": "MyCups",
  "productType": "Lids",              // любой свой идентификатор
  "typeKeywords": ["крышк"],          // как этот тип называет Bitrix
  "output": "{base}/Lids",            // куда складывать готовые
  "templateFolder": "{templates}/11_Lids",
  "articles": "lids"                  // таблица «артикул → файл» из articleTables
}
```

Порядок продуктов = порядок проверки, частные случаи выше общих.

Рядом лежит `catalog.schema.json` — VS Code подсказывает поля и подсвечивает
опечатки прямо при вводе. После правки нажмите **Настройки → Проверить каталог**:
она сверит описание и наличие всех файлов шаблонов.

Поднимите `"version"` — она видна в настройках, по ней понятно, кто отстал.

## Новое рабочее место

Дизайнер запускает с сетевого диска **`Y:\Soft\CupsForge
elease\install.cmd`** —
двойной клик. Скрипт скопирует программу в профиль пользователя, создаст ярлык
на рабочем столе и предложит запустить. Права администратора не нужны.

Дальше программа сама покажет мастер, если рабочих папок на машине нет. В офисе
он не появляется — там всё на своих местах.

- **В офисе** — ничего делать не надо.
- **Дома** — указать папку STAKANY, нажать «Разложить по офисной структуре»,
  при необходимости «Создать недостающие папки». Illustrator находится сам,
  любая версия.

Шаблоны и `catalog.json` дизайнер копирует с сервера через RDP — они нужны
вместе, поэтому и лежат рядом.

## Выложить новую версию

```
publish.cmd -Notes "добавлены крышки"
```

Версию поднимать **не нужно** — она считается из git: старшая часть из
`<Version>` в `CupsForge.csproj`, младшая — число коммитов. Забыть невозможно.
Не указали `-Notes` — возьмётся заголовок последнего коммита.

Через `.cmd`, а не `.ps1` напрямую: Windows по умолчанию запрещает запуск
сценариев PowerShell, а прав администратора, чтобы снять запрет, обычно нет.
Обёртка обходит политику на один запуск, ничего не меняя в системе.

Поднимите `<Version>` в `CupsForge/CupsForge.csproj`, запустите скрипт. Он
прогонит самопроверку, соберёт, выложит на `Y:\Soft\CupsForge\release` и обновит
указатель. У дизайнеров при следующем запуске появится полоска «Доступна версия».

Обновление ставится в профиль пользователя (`%LOCALAPPDATA%`), **права
администратора не нужны**. Работающий файл заменить нельзя, поэтому подмену
делает короткий скрипт: ждёт закрытия программы и запускает её заново.

На удалёнке сетевой раздачи нет — там новую версию забирают вместе с шаблонами.
Это не проблема: каталог меняется часто, программа редко.

## Самопроверка

```bash
dotnet run --project Tests/SelfCheck
```

248 проверок: пути, выбор шаблонов, разбор текста из Bitrix, создание проектов
целиком в песочнице (с посимвольной сверкой `args.txt`), обновления и интерфейс —
включая настоящее открытие окна и нажатия по кнопкам. Плюс кодировки скриптов
и то, что прогон не трогает профиль рабочего места.

Ожидаемые значения там — **не «как получилось»**, а как программа вела себя до
рефакторинга. Покраснело — значит поведение поехало.

## Доступ к Bitrix

Работа идёт по готовому **ключу доступа**, который выдаёт тот, кто ведёт Bitrix.
Вставляется в самой программе: **шестерёнка → ДОСТУП К BITRIX**.
Рядом кнопка «Проверить связь» — сразу видно, принял сервер ключ или нет.

Ключ можно вставлять как есть или с приставкой «Basic» —программа разберётся.
Хранятся в профиле рабочего места (`%APPDATA%\CupsForge\profile.json`) и в
репозиторий не попадают.

Нужны только для загрузки заказа по ссылке — ручной ввод работает и без них.

`CupsForge/appsettings.json` остался запасным вариантом для уже настроенных
машин. В репозитории его нет, есть только `appsettings.example.json`.
