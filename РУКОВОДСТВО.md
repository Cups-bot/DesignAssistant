# CupsForge — руководство

Всё, что нужно, чтобы вести программу: что где лежит, как выпустить версию,
что отправить дизайнерам, как обновлять шаблоны и каталог.

Про устройство изнутри — [ARCHITECTURE.md](ARCHITECTURE.md).
Памятка для дизайнеров, которую можно переслать, — [Инструкция-удалёнка.md](Инструкция-удалёнка.md).

---

## 1. Три вещи, которые нужно помнить

| Что | Чем обновляется | Как часто |
|---|---|---|
| **Программа** | `publish.cmd` | редко |
| **Шаблоны и каталог** | `push-templates.cmd` | часто |
| **Настройки рабочего места** | у каждого свои, вы их не трогаете | — |

Это три разных срока жизни, и они обновляются **независимо**. Правка каталога
не требует выпуска программы, и наоборот.

---

## 2. Карта файлов

### Что запускаете вы

| Файл | Зачем |
|---|---|
| **`publish.cmd`** | Выпустить новую версию программы. Собирает, прогоняет самопроверку, выкладывает. |
| **`push-templates.cmd`** | Выложить шаблоны и каталог. Сам поднимает версию каталога. |
| **`sync-icons.cmd`** | Пересобрать значки после правки `Icons\*.svg`. |

У каждого есть `.ps1` с той же логикой. Запускать нужно **`.cmd`**: Windows
по умолчанию запрещает запуск сценариев PowerShell, а прав администратора,
чтобы снять запрет, обычно нет. Обёртка обходит запрет на один запуск,
ничего не меняя в системе.

`dist-common.ps1` — общий код скриптов (ключ GitHub, работа с раздачей).
Сам по себе не запускается.

### Что правите вы

| Файл | Что задаёт |
|---|---|
| **`Core\catalog.json`** | Какие бывают продукты, где их шаблоны, куда складывать готовое. **Главный файл.** |
| `Core\catalog.schema.json` | Схема к нему: VS Code подсказывает поля и подсвечивает опечатки. |
| **`Icons\*.svg`** | Значки. Двадцать файлов, поле 24×24. Правятся в Illustrator. |
| `CupsForge\Theme\Tokens.xaml` | Цвета, размеры, шрифты, тайминги, **габарит окна**. |
| `.distignore` (рядом с шаблонами) | Что не выкладывать в раздачу. Образец — `distignore.example`. |

### Ядро — предметная область

`Core\` — отдельный проект **без интерфейса**. Попытка тронуть окно отсюда
не соберётся: так проверяется, что слои не смешались.

| Файл | Отвечает за |
|---|---|
| `Catalog.cs` | Модель каталога, подбор продукта под заказ, проверка описания. |
| `CatalogService.cs` | Откуда взять каталог: рядом с программой → папка шаблонов → копия внутри. |
| `MachineProfile.cs` | Профиль машины: папки, Illustrator, доступ к Bitrix. |
| `PathResolver.cs`, `Paths.cs` | `{templates}` → настоящая папка на этой машине. |
| `ProjectBuilder.cs` | **Единственная** процедура создания проекта. |
| `TemplateResolver.cs` | Какой файл шаблона взять под заказ. |
| `IllustratorLocator.cs` | Поиск Illustrator: реестр, потом Program Files. |
| `AppUpdates.cs` | Обновление программы: два канала, Velopack. |
| `DiagnosticLog.cs` | Журнал на диск, вычистка ключа, срок хранения. |
| `Distribution*.cs` | Раздача шаблонов: опись, отпечатки, докачка изменившегося. |
| `BuildRequest.cs`, `DesignSpec.cs`, `Enums.cs` | Мелкие общие типы. |

### Приложение — окно

| Файл | Отвечает за |
|---|---|
| `AutoWindow.xaml(.cs)` | Главное окно: состояния, уведомления, журнал. |
| `SettingsPanel.xaml(.cs)` | Настройки — панель справа внутри окна. |
| `ManualPanel.cs` | Ручной ввод; списки строятся из каталога. |
| `FixSheet.cs` | Лист правки одного поля поверх результата. |
| `Collapsing.cs`, `DockTab.xaml(.cs)` | Сворачивание к краю экрана и язычок. |
| `SyncPanel.cs` | Загрузка шаблонов из раздачи. |
| `Theme\` | Токены, значки, стили контролов, скругление окна. |
| `Services\` | Bitrix: запрос, разбор ответа, проверка связи, разбор ссылки. |

### Самопроверка

`Tests\SelfCheck\` — **247 проверок** одним прогоном:

```bash
dotnet run --project Tests/SelfCheck
```

Открывает настоящее окно и нажимает в нём кнопки. Прогоняется автоматически
перед каждым выпуском — если красное, выпуск не состоится.

## 3. Выпустить новую версию программы

```
publish.cmd -Notes "добавлены крышки"
```

**Версию поднимать не нужно** — она считается из git. Забыть невозможно.
Не указали `-Notes` — возьмётся заголовок последнего коммита.

Что произойдёт:

1. Прогонится самопроверка. Красное — выпуск отменяется.
2. Соберётся программа.
3. Упакуется в формат Velopack, попадёт на `Y:\Soft\CupsForge\release`.
4. Зальётся в публичную раздачу на GitHub (нужен ключ — см. ниже).

### Что появится в папке выпуска

| Файл | Что это |
|---|---|
| **`CupsForge-win-Setup.exe`** | **Это отправляют новым дизайнерам.** Один файл, двойной клик. |
| `CupsForge-<версия>-full.nupkg` | Полный пакет. Нужен раздаче, руками не трогать. |
| `CupsForge-<версия>-delta.nupkg` | Разница с прошлой версией. Её и качают те, у кого программа уже стоит. |
| `releases.win.json`, `RELEASES` | Опись. Программа читает её, чтобы понять, есть ли новое. |
| `CupsForge-win-Portable.zip` | Версия без установки. В обычной работе не нужна. |

**Ничего из папки не удаляйте.** Без прошлых версий рядом не с чем считать
разницу, и каждое обновление снова будет весить как вся программа —
76 МБ вместо 300 КБ.

### Из дома, где нет ни `Y:`, ни ключа

```
publish.cmd -Destination D:\проба -SkipDist
```

Соберёт всё в `D:\проба`, никуда не отправляя. Чтобы просто посмотреть окно,
выпуск не нужен вовсе:

```bash
dotnet run --project CupsForge
```

### Ключ GitHub

Для заливки в публичную раздачу нужен ключ с правом записи в
`Cups-bot/CupsForge-public`. Скрипт попросит его один раз и запомнит.

Создать: **github.com → Settings → Developer settings → Personal access tokens
→ Fine-grained tokens**, доступ только к этому репозиторию, права
**Contents: Read and write**.

## 4. Что отправить дизайнеру

### Новому — один файл

`CupsForge-win-Setup.exe`. Взять можно откуда угодно:

- **в офисе** — `Y:\Soft\CupsForge\release\`;
- **из дома** — из публичной раздачи на GitHub, ссылкой.

Дизайнер запускает двойным кликом. Программа встанет в его профиль, появятся
ярлыки на рабочем столе и в меню Пуск. **Права администратора не нужны.**

Перешлите ему [Инструкцию-удалёнку](Инструкция-удалёнка.md) — там всё, что
ему нужно знать, без технических подробностей.

### Тому, у кого программа уже стоит — ничего

Он увидит полоску «Доступна версия» при следующем запуске и нажмёт «Обновить».
Скачается только изменившееся.

### Разовое исключение

У кого стоит версия **до 3.0.45**, обновиться сами не смогут: прежний формат
раздачи новый не понимает. Им нужно **один раз** запустить `Setup.exe`.
Дальше всё пойдёт само. Это последний ручной обход.

## 5. Обновить шаблоны и каталог

```
push-templates.cmd -WhatIf
```

Сначала **всегда с `-WhatIf`**: покажет, что уедет, ничего не трогая.
Посмотрели — запускайте без него.

```
push-templates.cmd
```

### Что произойдёт

1. Если `catalog.json` изменился — **версия поднимется сама**, дата проставится.
   Не менялся — версия не тронется.
2. Посчитаются отпечатки всех файлов.
3. Зальётся только то, чего в раздаче ещё нет.
4. Обновится опись.

Дизайнеры получат новое при следующем запуске программы: сама скачает
изменившееся и перечитает каталог. **Ничего им говорить не нужно.**

### Добавить новый вид продукции

Пересобирать программу **не нужно**. Всё в `Core\catalog.json`:

```jsonc
{
  "id": "mycups-lids",
  "title": "MyCups — крышки",
  "typeTitle": "Крышки",              // как назвать в списке ручного ввода
  "brand": "MyCups",
  "productType": "Lids",              // любой свой идентификатор
  "typeKeywords": ["крышк"],          // как этот тип называет Bitrix
  "output": "{base}/Lids",            // куда складывать готовые
  "templateFolder": "{templates}/13_Lids",
  "articles": "lids"                  // таблица «артикул → файл»
}
```

Порядок продуктов = порядок проверки: **частные случаи выше общих**.

Проверить, что не ошиблись: **шестерёнка → КАТАЛОГ ПРОДУКТОВ → Проверить**.
Сверит описание и наличие всех файлов шаблонов.

### Кто отстал

Версия каталога видна в подвале журнала: «каталог v3 · 2026-08-02».
Если в раздаче есть свежее, там же появится «доступна v4».

## 6. Значки

Лежат в `Icons\` — двадцать `.svg`, поле 24×24. Правятся в Illustrator,
Figma, Inkscape. После правки:

```
sync-icons.cmd
```

Он пересоберёт `CupsForge\Theme\Icons.xaml`. **Забыть нельзя** — самопроверка
покраснеет и назовёт разошедшиеся файлы.

Одно правило: рисуйте **только контурами**. Останется `<circle>` или `<rect>` —
скрипт предупредит, что фигура потеряется. В Illustrator: `Object → Path →
Convert to path`.

---

## 7. Внешний вид

Всё в `CupsForge\Theme\Tokens.xaml`: цвета, размеры, шрифты, тайминги.
Ни одно значение не написано по месту — если нашли в разметке `#38BDF8`,
это ошибка.

**Габарит окна** — там же:

```xml
<sys:Double x:Key="Size.Window">390</sys:Double>
<sys:Double x:Key="Size.WindowHeight">390</sys:Double>
```

Уменьшить окно = поменять два числа. Все состояния подстроятся: окно не растёт
ни от чего — журнал шторкой снизу, настройки панелью справа, правка листом
поверх.

## 8. Если у дизайнера что-то не работает

Попросите файл журнала: **шестерёнка → ДИАГНОСТИКА → Показать файлы журнала**.
Откроется папка, в ней файл на каждый день, хранятся две недели.

**Ключ доступа к Bitrix в журнал не попадает** — вычищается при записи.
Файл можно пересылать спокойно.

---

## 9. Порядок при любой правке

1. Поправили.
2. `dotnet run --project Tests/SelfCheck` — должно быть зелёным.
3. Закоммитили.
4. `publish.cmd` — если правка в программе, а не в каталоге.

Никогда не выкладывайте с красной самопроверкой: `publish.cmd` этого
и не даст, но и вручную обходить не стоит — она ловит то, что глазами
не видно.
