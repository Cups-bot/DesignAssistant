# CupsForge — введение в курс дела

Читается за десять минут. После него понятно, зачем программа существует,
как устроена и куда смотреть, чтобы что-то поменять.

---

## 1. Что она делает

Дизайнер получает заказ: «сделать дизайн стакана DW90-430 для CarBar, офсет,
немелованный». Раньше он вручную создавал папку с правильным именем, искал нужный
из сотни .ai-шаблонов, копировал его, писал рядом текстовый файл с параметрами
и открывал в Illustrator скрипт подготовки.

Программа делает это за одно нажатие:

```
папка «132583 CarBar ST DW90-430»
├── 132583 CarBar ST DW90-430.ai      ← копия нужного шаблона
└── In/
    └── args.txt                       ← параметры для JSX-скрипта
```

Плюс запускает Illustrator и прогоняет в нём скрипт. Параметры заказа берутся
из Bitrix по ссылке либо вводятся руками.

---

## 2. Задача, ради которой всё переписано

Первая версия работала у одного человека. Перенести её другому не получалось:

- пути к папкам были **константами в коде** (`Y:\STAKANY\...`), а у дизайнера
  на удалёнке своя файловая структура;
- путь к Illustrator был зашит с номером версии — у одного 2025, у другого 2022;
- список продуктов и шаблонов лежал в словарях C#, поэтому новый вид продукции
  требовал пересборки и раскладки программы всем;
- логика существовала **в двух копиях** — в ручном редакторе и в автоматической
  программе, и копии успели разойтись.

Отсюда главный принцип, которому подчинено всё остальное.

---

## 3. Главная идея: три слоя, три срока жизни

Всё, что раньше было перемешано в коде, разнесено по трём слоям. Критерий
разделения — **как часто это меняется и у кого**.

| Слой | Что описывает | Где лежит | Меняется |
|---|---|---|---|
| **Профиль машины** | папки, версия Illustrator, ключ Bitrix | `%APPDATA%\CupsForge\profile.json` | у каждого своё |
| **Каталог** | какие бывают продукты, где их шаблоны, куда складывать | `catalog.json` в папке шаблонов | раз в квартал |
| **Код** | скопировать, записать, запустить | эта программа | редко |

**Физических путей в коде нет вообще.** Код и каталог оперируют *логическими
корнями* в фигурных скобках: `{templates}`, `{out.mycups}`, `{base}`. Профиль
превращает их в настоящие папки. Поэтому одна и та же сборка работает и в офисе
с диском `Y:`, и дома, где всё лежит в `D:\Work`.

Проверить, что слой не протёк: `Shared/Paths.cs` — там нет ни одной строки
с буквой диска.

## 4. Каталог — центральное понятие

`Shared/catalog.json` (265 строк) описывает предметную область целиком:

```jsonc
{
  "id": "mycups-choko",
  "title": "MyCups — шоколад",
  "typeTitle": "Шоколад",             // как назвать в списке ручного ввода
  "brand": "MyCups",
  "productType": "Choko",             // свободный идентификатор, не enum
  "typeKeywords": ["шокол"],          // как этот тип называет Bitrix
  "output": "out.mycups",             // куда складывать (или "{base}/Lids")
  "naming": "plain",                  // или "pantone" — правило имени папки
  "argsTech": "offset",               // что писать в args.txt
  "templateFolder": "{templates}/8_Choko",
  "variants": {                       // выбор шаблона по вкусу, а не артикулу
    "Dark": { "title": "Тёмный", "file": "CHOKO_Dark.ai",
              "keywords": ["тёмн", "темн", "горьк"] }
  },
  "defaultVariant": "Milk"
}
```

Продукты проверяются **сверху вниз, побеждает первый подошедший** — поэтому
частные случаи (флексо-офсет) стоят выше общих (флексо-всё-остальное).

Отдельный раздел `bitrixWords` описывает, какими словами Bitrix называет
направления, способы печати, материалы. Там действует другое правило —
**побеждает самое длинное совпадение**: «Пластиковый стакан» содержит и «пластик»,
и «стакан», а «немелованный» содержит «мелован». По порядку это разрешить нельзя,
по длине — можно.

Из каталога берётся не только логика, но и **интерфейс**: список направлений,
типов продуктов, вкусов. Новый продукт появляется в выпадающих списках сам —
рисовать для него кнопку не нужно.

Ключевое решение: **тип продукта и вариант — строки, а не `enum`**. Пока они были
перечислениями, «крышки» всё равно требовали правки кода. Enum'ы остались только
там, где набор значений действительно закрыт: направление, способ печати, материал.

Рядом `catalog.schema.json` — VS Code подсказывает поля и подсвечивает опечатки
прямо при вводе. Это заменяет экранный редактор каталога.

## 5. Как проходит заказ

Оба входа сходятся в одну точку — это и есть смысл рефакторинга.

```
ссылка на Bitrix                    ручной ввод
      │                                   │
 BitrixClient      (HTTP)                 │
      │                                   │
 BitrixMapper  ← слова из каталога        │
      │  «Бумажный стакан» → Cups         │
      ▼                                   ▼
 ResolvedDesign ──────► BuildRequest ◄──── поля панели
                             │
                             ▼
                      ProjectBuilder
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
  Catalog.Require    TemplateResolver        PathResolver
  какой продукт      какой файл шаблона      где это на диске
        └────────────────────┼────────────────────┘
                             ▼
              папка + .ai + args.txt + Illustrator
```

`BuildRequest` (25 строк) — узкое место, через которое проходит всё. Хотите
добавить третий способ ввода — соберите `BuildRequest`, остальное уже работает.

## 7. Решения, которые выглядят странно, пока не знаешь почему

**Каталог лежит в папке шаблонов, а не рядом с программой.** Он без шаблонов
бесполезен. Дизайнер на удалёнке копирует папку `_Templates` через RDP и получает
и то, и другое разом. Развести их по разным каналам — гарантированно получить
рассинхрон.

**Программа не запускается с сетевого диска.** Пока кто-то работает, файл занят
и новую версию не выложить. Поэтому на диске лежит раздача, а работает каждый
со своей копии в `%LOCALAPPDATA%`. Оттуда же обновляется — прав администратора
не требуется.

**Обновление подменяет файл через `.cmd`-скрипт.** Работающий exe сам себя
переписать не может. Скрипт ждёт выхода программы, подменяет файл и запускает
заново. Внутри скрипта только латиница, а пути передаются **аргументами**:
`cmd.exe` читает `.cmd` в кодировке консоли, и кириллица в имени пользователя
(`C:\Users\Дмитрий\`) превратилась бы в мусор.

**Строка «Печать» в ручном вводе иногда исчезает.** Она показывается, только
если разные значения приводят к **разным продуктам**. У шоколада способ печати
задан каталогом жёстко — выбирать нечего, и строки нет. Считается по каталогу,
а не прописано.

**Ошибка разбора чинится листом на одно поле.** Bitrix ошибается обычно
в одном поле из семи: не узнал материал, не разобрал вкус. Клик по строке
результата открывает лист ровно с этим полем и возвращает в тот же результат.
Открывать ради этого ручной ввод целиком значит заставить перезаполнить шесть
верных полей ради одного неверного. Варианты берутся из каталога, поэтому
новый материал или вкус появляется в листе сам.

Карандаш рисуется не у всех строк: у шоколада нет материала, у MyCups нет
страны, и обещать там правку — врать. Что можно править, спрашивается
у каталога.

**Настройки — панель внутри окна, а не отдельное окно.** Модальное окно
560×680 добавляло второй пункт в таскбар и уводило от заказа, который человек
как раз разбирает. Побочно оно было непроверяемо: прогон вис на модальном
диалоге, закрыть его в тесте некому, — и ради этого пришлось заводить
подменный шов. Панель проверяется как обычная разметка.

**Значки лежат отдельными SVG, а в программу едет геометрия.** WPF не умеет
SVG, а библиотека ради двух десятков значков весит больше самих значков.
Поэтому `Icons/*.svg` — источник, который правит дизайнер, `sync-icons.cmd`
переносит их в `Icons.xaml`, а самопроверка сверяет одно с другим: забытый
запуск скрипта краснеет и называет разошедшиеся файлы.

**Мастер настройки решает по наличию папок, а не по наличию профиля.** В офисе
`Y:` на месте — окно не появляется. Дома появляется. Если у дизайнера сменилась
буква диска, появится снова. Отказ от мастера — не «ничего не произошло»:
«Создать проект» остаётся недоступной, а причина висит над кнопкой. Иначе
дизайнер получал вместо «настройте папки» невнятное «файл шаблона не найден».

**Пропавший Illustrator не подменяется найденным.** Соблазн велик — рядом
стоит другая версия, запусти её. Нельзя: версию выбирают под JSX-скрипт,
и молча открытый 2025 вместо выбранного 2022 портит макет, ничего не сообщая.
Программа называет, что пропало и что найдено рядом, а выбирает человек.
Это же правило спасает самопроверку: подмена открывала настоящий Illustrator
с файлом-заглушкой из песочницы, тот показывал «ID: -54» и ждал нажатия «ОК».

**Обновление спрашивает «можно ли», прежде чем предложить кнопку.** Запуск не
из своей папки обновляться не должен — иначе перепишется раздача, общая для
всех. Раньше это выяснялось по нажатию, и отказ выглядел как поломка.

**`.ps1` сохраняются с BOM.** Windows PowerShell 5.1 читает файлы без BOM как
ANSI: кириллица разваливается, парсер спотыкается о кавычки внутри неё и скрипт
не запускается вовсе. У `.cmd` наоборот — BOM ломает первую строку.

**В `.cmd` только латиница — вообще везде, не только в скрипте обновления.**
`cmd.exe` читает `.cmd` в кодировке консоли, а не в UTF-8. Кириллица в обычном
`rem`-комментарии разваливается, и обломки иногда выглядят для `cmd` как
разделитель команд: строка распадается, сыплется «не является внутренней или
внешней командой». Всё, что читает человек, печатает `.ps1`. Самопроверка это
стережёт — и BOM, и латиницу, и то, что каждый `.ps1` действительно читается
установленным в системе PowerShell.

**Локальные переменные в `.ps1` не называют как параметры.** Имена в PowerShell
нечувствительны к регистру, а параметр объявлен с типом. `$templates = ...` при
параметре `[string] $Templates` молча приводит массив к строке. Так в описи
раздачи не оказывалось ни одного шаблона — при том что прогон выглядел успешным:
вложения залиты, качать дизайнеру нечего.

**Самопроверка уводит профиль в песочницу.** Она открывает настоящее окно и
нажимает в нём кнопки, а окно сохраняет профиль на диск. Без подмены папки
каждый прогон затирал настройки рабочего места путями во временную папку,
которую сам же и удалял. Отдельная проверка следит, что профиль не тронут.

## 8. Что менять и где

| Задача | Куда смотреть |
|---|---|
| Новый вид продукции | `catalog.json` — и всё |
| Новый артикул к существующему продукту | `catalog.json`, раздел `articleTables` |
| Bitrix стал называть тип по-другому | `catalog.json`, `typeKeywords` |
| Изменилось содержимое `args.txt` | `Shared/ProjectBuilder.cs` |
| Новое поле в панели ручного ввода | `CupsForge/ManualPanel.cs` + разметка |
| Новый логический корень | `MachineProfile.Root` |
| Выложить новую версию | поднять `<Version>`, запустить `publish.cmd` |
| Выложить шаблоны | `push-templates.cmd -WhatIf`, посмотреть, потом без `-WhatIf` |
| Что-то не должно уезжать в раздачу | `.distignore` рядом с шаблонами (копия — `distignore.example`) |

После любой правки — `dotnet run --project Tests/SelfCheck`.

## 9. Незакрытое

- **Ключ доступа к Bitrix лежал в истории git открытым.** Его нужно сменить;
  теперь это безболезненно — вводится в настройках у каждого.
- Каталог правится только текстом. Экранного редактора нет и, пока правит один
  человек, скорее всего не нужен — схема закрывает опечатки.
- **Первая копия на новой домашней машине** приезжает руками: `install.cmd`
  требует сетевой диск, а раздачу тянет уже установленная программа.

## 10. С чего начать чтение кода

1. `Shared/catalog.json` — что программа вообще умеет
2. `Shared/ProjectBuilder.cs` — что происходит по нажатию кнопки
3. `Shared/Catalog.cs`, метод `Match` — как выбирается продукт
4. `Tests/SelfCheck/LogicChecks.cs` — как это выглядит в примерах

Четырёх файлов достаточно, чтобы понять систему. Остальное — детали.
